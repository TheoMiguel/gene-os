# GENE_OS

A molecular biology workstation that runs entirely in the browser. Restriction analysis, primer design,
virtual PCR, cloning, plasmid maps, alignment and sequence annotation, offline and without an account.

Every analysis runs on the user's own machine. The site is static files, so hosting costs nothing and no
sequence ever leaves the browser. Only the optional database lookup uses the network.

## Running it

```
pnpm install
pnpm dev
```

Then open the address it prints. `pnpm build` writes the deployable site to `dist/`.

| Command | What it does |
|---|---|
| `pnpm dev` | Development server with hot reload |
| `pnpm build` | Type-check and build the static site |
| `pnpm test` | Run the test suite |
| `pnpm lint` | Check formatting and lint rules |
| `pnpm typecheck` | Type-check without building |

## How the biology is kept honest

Nobody on this project is a biologist, so no biological result is trusted because the code looks right.
Every value the engine computes is compared against an established tool, and the comparison is committed:

- **Biopython 1.88** for translation, molecular weight, protein properties, restriction digests, sequence
  file parsing and pairwise alignment scores.
- **primer3 2.4** for melting temperatures, hairpins, dimers and primer design quality.
- Published reference data, with its source recorded, for the enzyme catalog (REBASE, via Biopython),
  codon usage tables (Kazusa), commercial ladders and the example plasmids (public NCBI records).

The comparison values live in `tests/oracle/` and are regenerated by the scripts in `scripts/oracle/`.
Those scripts need Python with Biopython and primer3-py; the test suite does not, because the expected
values are committed. Set the Python environment up with:

```
uv venv .venv && uv pip install --python .venv/bin/python biopython primer3-py
```

## Layout

| Folder | What lives there |
|---|---|
| `src/engine/` | All analysis. Pure functions, no DOM and no network, so it also runs in a worker. |
| `src/formats/` | Readers and writers for FASTA, GenBank, EMBL, SnapGene, AB1 and raw text. |
| `src/data/` | Catalogs: enzymes, features, ladders, codon tables, matrices, example plasmids. |
| `src/state/` | The open documents, the shared selection, settings and undo. |
| `src/workers/` | Runs the heavy scans off the main thread. |
| `src/ui/` | The interface. One file per analysis view under `src/ui/views/`. |
| `src/net/` | The only code that touches the network: NCBI, ENA and UniProt lookups. |
| `src/project/` | The project file and automatic session restore. |
| `src/report/` | The PDF comparison report, generated in the browser. |

[docs/architecture.md](docs/architecture.md) explains the data-shape rules, the chief one being that
coordinates are 0-based and half-open everywhere except on screen, and that a feature crossing the origin
of a circular molecule is stored as two segments.

## Known limitations

- **ENA lookups may fail.** The European Nucleotide Archive's sequence download service was unreachable
  during development, while its search service answered normally. The app reports the failure and names the
  service. NCBI serves the same records, so nothing is lost in practice.
- **pET-28a(+) is not among the example plasmids.** The public databases carry only unannotated patent
  copies of it, and Addgene requires a sign-in to download sequences. A labelled related construct ships
  instead, rather than an invented record.
- **Some cloning reference data is unverified.** Parts of the Gateway att-site and TOPO data in
  `src/data/cloning-*.json` could not be checked against a citable public source. Each file records what
  its source was. Treat those two methods as a guide, not as a protocol.
- **Local and overlap alignment are limited by memory**, to roughly 10 kb against 10 kb. Past that the app
  says so instead of freezing. Global alignment reaches far longer sequences when they are similar.
- **Browser shortcuts win.** Ctrl+N and Ctrl+W belong to the browser in a normal tab, so they only reach
  the app in an installed window or a desktop build.
- **Multiple alignment is not Clustal.** It is a correct, deterministic progressive alignment, but its
  columns can differ from Clustal's on hard cases.

## Licence and data sources

The example plasmids, enzyme catalog and codon tables come from public databases, each recorded with its
accession or dataset in the file beside it. The test fixtures under `tests/fixtures/formats/` come from the
Biopython project's own test suite; see the README there for their origin and licence note.
